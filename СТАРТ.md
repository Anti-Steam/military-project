# СТАРТ — как запустить систему и работать в ней

АИС учета личного состава, допусков и суточных нарядов.
Полная техническая спецификация — `README.TXT`; этот файл — только чтобы
запустить и начать работать.

> **Все данные в репозитории — синтетические.** Реальные данные личного
> состава в репозиторий и на стенд разработки не кладутся никогда.

---

## 1. Что нужно на компьютере

| Что | Зачем | Проверить |
|---|---|---|
| Linux (разработка — любой, цель — Astra Linux) | | |
| Node.js 22 или новее | само приложение | `node -v` |
| Docker с Compose | база данных PostgreSQL 16 | `docker compose version` |
| LibreOffice | приказы Word → PDF, чтение DOCX при разборе | `soffice --version` |
| poppler-utils (`pdftotext`) | чтение PDF при разборе приказов | `pdftotext -v` |
| git | получить и обновлять код | `git --version` |

Без LibreOffice и poppler система работает, но приказы не пересохраняются в
PDF и не разбираются автоматически.

## 2. Первый запуск

```bash
git clone git@github.com:Anti-Steam/military-project.git
cd military-project

npm ci                         # зависимости служебных скриптов
npm ci --prefix services/app   # зависимости приложения
```

Дальше — один из двух вариантов.

### Вариант А. С демо-набором (рекомендуется для работы и показа)

Готовая «живая» часть: подразделения со штатом, ~170 человек, допуски,
оружие, заполненный график нарядов, приказы, учетные записи разных ролей.

```bash
./start          # первый раз: создаст .env и базу; дождитесь «Сервер запущен», затем Ctrl+C
npm run demo:load   # зальет демо-набор (спросит подтверждение — введите «да»)
./start          # запуск
```

Откройте **http://localhost:3000**. Учетные записи демо-набора, пароль у всех
**`demo`**:

| Логин | Роль | Что видит |
|---|---|---|
| `admin` | Администратор | все, включая учетные записи и журналы |
| `bvs` | Начальник службы | наряды, утверждение, допуски, отсутствия — по всей части |
| `rota1` | Командир подразделения | свое подразделение: люди, наряды своих постов, оружие |
| `komandir1` | Пользователь | «Мои данные» и график |

### Вариант Б. Чистая база

```bash
./start
```

База заполнится базовым синтетическим набором из миграций (люди, посты,
допуски — без нарядов и приказов). При первом запуске в консоли **один раз**
печатается временный пароль администратора — запишите его; при первом входе
система попросит его сменить.

## 3. Ежедневная работа со стендом

| Действие | Команда |
|---|---|
| Запустить (и применить новые миграции) | `./start` |
| Остановить приложение | `Ctrl+C` в окне, где запущен `./start` |
| Остановить базу | `docker compose down` (данные сохраняются) |
| **Стереть базу полностью** | `docker compose down -v` ⚠ необратимо |
| Вернуть демо-набор | `npm run demo:load` ⚠ заменяет все данные в базе |
| Какие миграции применены | `npm run migrate:status` |
| Разработка с автоперезапуском | `cd services/app && npm run dev` |
| Резервная копия базы и файлов приказов | `node --env-file=.env scripts/backup.js` → папка `backups/` |

Повторный `./start` сам останавливает прежний экземпляр — это обычный способ
применить изменения кода.

**Обновиться с GitHub:** `git pull`, затем `./start` (новые миграции
применятся сами).

## 4. Как устроена работа в системе

Вверху — разделы (видны те, на которые есть права). Справа — **«Мои данные»**:
свои наряды, допуски, отсутствия, оружие, где вы вошли, смена пароля.

| Раздел | Что там делают |
|---|---|
| **График нарядов** | Календарь нарядов по месяцам. «Назначить автоматически» — система сама подберет состав по очереди и правилам (допуски, отсутствия, отдых, оружие). Проверить, поправить, «Утвердить», распечатать приказ. |
| **Наряды** | Виды нарядов и их посты, время заступления, отдых после сдачи, вес, шаблон приказа. Порядок — перетаскиванием. |
| **Выходные** | Праздничные и перенесенные дни: от них зависят вес наряда и правила «только в выходные». |
| **Оружие** | Оружие по подразделениям: закрепление за людьми, склад, перемещение перетаскиванием; «занято» — по приказу (караул и т. п.). |
| **Личный состав** | Люди по подразделениям, поиск, прием; карточка человека — данные, допуски, отсутствия, наряды, очередь, оружие, история изменений. |
| **Строевая записка** | Записка на дату (по штату / по списку / на лицо / причины), печать. |
| **Приказы** | Реестр: «Допуски», «Отсутствия», «Прочие» (свои виды — например, караул), «Дежурства». Приказ с файлом можно **разобрать**: система найдет людей, сроки, допуски, оружие и предложит на проверку. «Словарь разбора» — чему система учится и свои виды приказов. |
| **Подразделения** | Структура части и штат: должности, перевод людей, командиры, ВРИО. |
| **Подбор** | Параметры очереди заступления, веса званий на постах, личные поправки — с пояснениями под каждым. |
| **Учётные записи** | Заведение пользователей, роли и точечные права, закрепленное подразделение, сеансы, «Журнал доступа». |
| **Журнал** | Кто, когда и что изменил в данных (было → стало). |

Типовой цикл: **Личный состав** (люди, допуски, отсутствия) → **Наряды**
(виды и посты) → **График нарядов** → «Назначить автоматически» → проверить →
«Утвердить» → печать приказа.

Командир подразделения видит и ведет **только свое подразделение** (со всеми
вложенными); администратор, заместители и начальники служб — всю часть.

## 5. Проверки (для разработчиков)

Проверки идут на **отдельной тестовой базе** и отдельном экземпляре
приложения (порт 3100) — рабочая база не трогается. Тестовая база
собирается из миграций, **не из демо-набора** (на заполненном графике часть
проверок не найдет свободных суток).

```bash
DB_NAME=military_review_test node --env-file=.env db/migrate.js
DB_NAME=military_review_test APP_PORT=3100 node --env-file=.env services/app/server.js &
DB_NAME=military_review_test CHECK_URL=http://localhost:3100 npm run check
npm test                     # чистые модульные проверки
npm run test:integration     # транзакции, права, миграции
```

После правки кода сервера тестовый экземпляр нужно перезапустить.
Правила работы с кодом — `CLAUDE.md`.

## 6. Обновить демо-набор в репозитории

Если в рабочей базе накоплены новые **синтетические** данные, которыми стоит
поделиться:

```bash
npm run demo:save      # снимок базы → db/demo/demo.sql и db/demo/storage/
git add db/demo && git commit -m "Демо-набор: ..." && git push
```

Снимок не содержит журналов, сеансов и настоящих паролей — у всех учетных
записей ставится пароль `demo`. **Снимать только с базы, где нет реальных
данных.**

## 7. Перед реальной эксплуатацией

Стенд разработки работает с послаблениями — перед боевым применением
**обязательно**:

- в `.env` убрать `PASSWORD_MIN_LENGTH=1` (минимум — 12 знаков);
- сменить все пароли (демо-пароль `demo` и пароль администратора);
- `NODE_ENV=production`;
- включить HTTPS в Nginx и `SESSION_SECURE=true`;
- Nginx должен передавать адрес клиента (`X-Forwarded-For`) — по нему
  работает блокировка входа;
- **не** заливать демо-набор: база заполняется реальными данными только в
  закрытом контуре.

## 8. Если что-то не так

| Сообщение / симптом | Что делать |
|---|---|
| «Не установлены зависимости» | `npm ci` и `npm ci --prefix services/app` |
| «Нет соединения с базой данных» | запущен ли Docker: `docker compose ps`; поднять: `docker compose up -d db` |
| «Порт 3000 занят» | закрыть другое приложение или поменять `APP_PORT` в `.env` |
| «Нет файла .env» (у `demo:load`) | сначала один раз `./start` |
| Приказ без PDF / «LibreOffice не найден» | установить LibreOffice, загрузить файл приказа заново |
| Не помню пароль администратора | войти другим администратором → «Учётные записи» → «Выдать новый временный пароль»; на стенде — `npm run demo:load` |
| Вход заблокирован после 3 ошибок | подождать 10 минут или «Разблокировать» в «Учётных записях» (блокировка — только с того компьютера) |
