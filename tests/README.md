# Проверки

`npm test` запускает автономные тесты без PostgreSQL и HTTP-сервера.
Для подробного списка на Node с поддержкой этой опции:
`node --test --test-isolation=none tests/*.test.js`.

Новые проверки автоматически подключены к общему запускателю `tests/run.js`:

| Файл в checks/ | Что проверяет |
| --- | --- |
| 130-inputs.js | Даты, идентификаторы, права, CSRF, multipart, двоичные данные, лимиты и ошибки потока |
| 140-calculations.js | Очередь, стабильная сортировка, праздники, смены, приоритеты и итоги строевой записки |
| 150-service-boundaries.js | Область подразделения, сроки и дубликаты допусков, состояния, имена |
| 160-database-integrity.js | Реальный откат создания и изменения справочника, история приказа и допуска |
| 170-backup.js | Файлы копии, DOC_STORAGE, SHA-256, восстановление документов, очистка при отказе |

Автономные проверки сервисов подменяют обращения к БД и восстанавливают их
в `finally`. Проверки резервных копий используют временные каталоги и замену
`pg_dump`; восстановление PostgreSQL ими не проверяется.

Полный прогон выполняется только на отдельной БД:

```sh
DB_NAME=military_review_test node --env-file=.env db/migrate.js
DB_NAME=military_review_test APP_PORT=3100 node --env-file=.env services/app/server.js
```

Во втором терминале:

```sh
DB_NAME=military_review_test CHECK_URL=http://localhost:3100 npm run check
```

Первая команда применяет миграции только к тестовой БД, вторая запускает
отдельный сервер на порту 3100. Последняя запускает все проверки.
Новые проверки БД создают синтетические записи и удаляют их либо откатывают
транзакцию. Запуск на рабочей БД запрещён.
